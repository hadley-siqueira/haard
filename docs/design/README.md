# Design decisions

Long-form design lives here, one record per decided subject, so that a
discussion spread over many sessions never loses a thread.

Each record is short on purpose: the context, the decision, its consequences,
and what was rejected and why. A subject is only written down once it is
settled; until then it sits in the agenda below.

**The rule: one subject per conversation, and the conversation is not over
until its record exists.**

Status is one of `open`, `decided` (with a link to its record) or `deferred`
(with the reason it can wait).

The state of the **code**, as opposed to the state of the decisions, is
[../STATE.md](../STATE.md).

| 1.25 | What `new T[n]` gives back, and where an array's length lives | `decided` — [0028](0028-a-heap-array-is-a-pointer.md), 2026-09-05, and implemented. | 1.27 | How Haard reaches a C library, until it has a foreign interface | `decided` — [0030](0030-eight-native-functions-for-io.md), 2026-09-05, and implemented, **temporary on purpose**. | 1.28 | What copying a value means | `decided` — [0031](0031-what-copying-a-value-means.md), 2026-09-05, and implemented. | 1.32 | What a `char*` reaching a `String` is, and what a constructor is called | `decided` — [0038](0038-everything-about-construction-is-init.md), 2026-09-06, and implemented. **Everything about construction is `init`**: [0031](0031-what-copying-a-value-means.md)'s `copy` is retired and the copy constructor is the `init` whose one parameter is the class itself — which forecloses `from`, `convert` and every other name, and leaves room for the `&&` overload a simplified move will need. And a `char*` reaching a `String` is a **call the compiler writes**: it used to name no constructor at all, because record 0026 emits `init` as a C++ constructor of one argument and C++'s own converting constructor ran it — record 0034's rule surviving in the compiler's own emission. | 1.24 | What a bare name on the left of `=` declares, and what a derived class may not redeclare | `decided` — [0027](0027-a-bare-name-that-declares.md), 2026-09-05, and implemented. `let` stays optional, and "in view" now includes a field of a **base** — so the decision moves out of the symbol phase, where a base is not yet a type, into the type phase and a new `ImplicitCollector`. It still does not ask the imports. And a derived class that declares a field a base already declares is an **error**: record [0020](0020-the-base-chain-in-a-lookup.md) makes a bare name in the base's own method still mean the base's, so two fields of one name cannot be told apart at the use |
| 1.21 | A `char*` where a `String` was asked for | `decided` — [0023](0023-a-char-pointer-becomes-a-string.md), 2026-09-03, and implemented. `String` **owns** its bytes, so a literal reaching one runs a constructor and this was never [0018](0018-implicit-conversion.md)'s first rule; `char*` → `String` goes **on 0018's list**, which answers the literal and the variable with one rule; and a literal matching the type it has when nothing asks outranks one that took a step, which is what gives `char*` the call. The list also moved into one place, `src/haard/type_table/coercion.{h,cpp}`, because it turned out only a **call** had ever known it — a return, a binding and an assignment refused the upcast 0018 allows | **Amended 2026-09-08**: a written **literal** left the list and became a **construction** by [0037](0037-the-bracket-literal-and-list.md)'s mechanism — the typer picks the class's `init(char*)`, writes it on the literal and the emitter writes that call, so the name `String` no longer matters for a literal and any class with that constructor is reached. A `char*` **value** is still this record's named entry, and the ranking is still this record's one step. Deleting the entry is the last step and waits on `T(args)`
| 1.16 | Interfaces | `decided` — **they do not exist.** Hadley, 2026-09-02: no interfaces and no syntax for them, so a class has one base and [0018](0018-implicit-conversion.md)'s rule 5 stays a number along a chain, permanently |

## Track 5 — the back end

| # | subject | status |
|---|---|---|
| 5.9 | What `for x in` means | `decided` — [0040](0040-for-in-is-an-iterator.md), 2026-09-06, and **built** 2026-09-08. A container gives back a **cursor**, and there is **one per container** so each walks the way it is fastest: `ListCursor<T>` follows `next`, `ArrayCursor<T>` holds a position. `iterator()`, `has_next()`, `next()`, and `x` is a **reference** — a copy of an element that owns something is refused by record 0031, so `for x in <an Array of Owner>` would not compile at all. A **fixed array is iterable**, by the length its type carries, which is why the lowering runs **after the types** rather than in the sugar pass — record 0039 is what made that possible. The index form — `while i < xs.length()` — was free and was rejected because `List`'s `operator[]` walks: a `for` loop would turn an O(n) method into an **O(n²)** loop silently. `for i in 0..10` becomes a plain loop with no `Range` class. Writing it moved the lowering from a phase of its own into the **type phase**, driven by the loop variable's candidate — a pass afterwards types `let y = x` in the body against nothing — and found that `..` is the **inclusive** spelling and `...` the exclusive one, which record 0040's own examples had the other way round |
| 5.10 | `Hash<K, V>`, and what a generic body may ask of its parameter | `decided` — [0042](0042-the-hash-and-what-a-generic-may-ask.md), 2026-09-08, and implemented. Hashing is an **overload set** (`hash_of`) and not a method, because [1.16](#) closed interfaces; the table is **open addressed**, three parallel buffers and linear probing; walking one gives back its **keys**. Writing it made the type phase skip a call whose argument is still a **type parameter** (record 0002, which the statement checker and the emitter already followed) and made an **operator's operand** go through the conversion an argument goes through — `s == "abc"` compiled here and was refused by g++ |
| 5.8 | What an operator on a class means, and whether the C++ may use its own | `decided` — [0034](0034-an-operator-is-a-method-with-an-unwritable-name.md), 2026-09-06, and implemented. `def operator[] : T&`, written against the word. The method's **name** is `operator[]`, which no identifier can be, so no source can call one by name and **nothing after the parser knows an operator was involved**. The C++ is a **method call** and never a C++ operator overload — Hadley's rule, and record 0025's argument against templates a second time. The mangling gained a word per punctuation character, which is load-bearing: `operator+` and `operator-` folded to one name. And a class that did **not** overload an operator is now an **error** rather than a fall-through, which closes a silent hole — `a != b` between two classes typed to `bool` and came out as a C++ `!=` that does not exist |
| 5.1 | What the back end emits, and whether it needs an intermediate representation | `decided` — [0025](0025-the-back-end-is-a-cpp-transpiler.md), 2026-09-03, and implemented. **C++**, emitted from the Ast and the ResolutionTable with no IR: [0019](0019-the-resolution-table.md) already annotates every node, and C++ is not lower than the source. Hadley has said an IR **will** be needed for a processor he is building, so the record names the three signals that would make this the wrong shape. `hdc --emit-cpp`, `tests/emitter/` |
| 5.2 | `init` and `destroy` in the output | `decided` — [0026](0026-init-and-destroy.md). | 5.5 | Where "can this class be built with no arguments?" is asked | `decided` — [0028](0028-a-heap-array-is-a-pointer.md), 2026-09-05, and implemented. In the **`TypeCollector`**, where a declaration gets its type and where the node to point at is: it was asked in the emitter, so `hdc file.hd` called a program fine and `--emit-cpp` called it broken, with a refusal that had no file, no line and no caret. All four ways in are covered — a field, a base, a local, a global. **Nothing is generated**: a class with no `init` already gets C++'s implicit constructor, which builds its class-typed fields down the chain, and a class that *wrote* an `init` taking arguments does not get a free one, or a written `init` would stop guaranteeing it ran |
| 5.6 | `def init : i32`, a constructor that gives something back | `open`, and nothing reports it. One check, and it belongs with the override checker's family |
| 5.3 | What the emitter still refuses | `open`: a hash literal (1.23), a tuple, a list, a closure, a range, `T[]` with no length. ~~A symbol~~ left the list on 2026-09-08 — [0041](0041-a-symbol-is-an-interned-name.md) makes it a builtin of its own and an entry in a table the emitter builds. ~~A template string~~ is gone from this list since 2026-09-06 — [0032](0032-how-a-template-string-is-lowered.md) takes it apart before the emitter is reached, and 5.4's Ast → Ast pass exists now. | 5.7 | How a template string is lowered | `decided` — [0032](0032-how-a-template-string-is-lowered.md), 2026-09-06, and **implemented**.
