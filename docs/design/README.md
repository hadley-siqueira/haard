# Design decisions

Long-form design lives here, one record per decided subject, so that a
discussion spread over many sessions never loses a thread.

Each record is short on purpose: the context, the decision, its consequences,
and what was rejected and why. A subject is only written down once it is
settled; until then it sits in the agenda below.

**The rule: one subject per conversation, and the conversation is not over
until its record exists.**

Status is one of `open`, `decided` (with a link to its record) or `deferred`
(with the reason it can wait).

The state of the **code**, as opposed to the state of the decisions, is
[../STATE.md](../STATE.md).

| 1.47 | The **precedence** of the operators, and whether the back end carries it | `decided` — [0057](0057-the-precedence-of-the-operators.md), 2026-09-10, and built. The order was only ever in the parser's shape and is written down now, in the README: **deliberately not C's**, with `**`, `|`, `^`, `&` and the shifts binding tighter than `*`. Two levels **change**. `not` stops being a second spelling of `!` and becomes a loose word above the comparisons, where Python has it, so `not a < b` asks about the comparison instead of typing `not` against an `i32`; `!` stays where C has it. `**` becomes **right associative**, which is what a power tower means. And the emitter wrote **no parentheses at all**, so C++ regrouped every expression the two languages disagree about — `println(4 + 3 & 1)` printed 1 where the tree says 5, with `hdc` right, g++ right and the program wrong. Each operand is asked what precedence **C++** would read it at now, which also fixes a `.` or a call on a looser left side and `- -a`, emitted as `--a`. **Not one of the 37 emitter goldens moved**: no test had ever written an expression the two languages read differently, which is how a defect of this shape survives. The same record then **built the four operators the table had and the compiler did not**: `**`, `in` and `not in` were in nobody's switch in the type phase and fell through its `default` to `INVALID_TYPE` in silence, while `//` and `>>>` were typed with no emission. `**` and `//` are calls to a helper written above the program (`//` **floors**, where C++'s `/` truncates, and emitting `/` would have been a different operator for negative operands only); `>>>` shifts through an unsigned of the same width; and **`a in b` is `b.contains(a)`**, the container asked for a method by name the way record [0040](0040-for-in-is-an-iterator.md) asks one for `iterator`. The type argument of a generic `contains` is written by the **compiler** out of the value's type, since `in` has nowhere to put a `<i32>` — so it waits on no inference — and a generic container's `contains` is a generic **method**, or record [0054](0054-a-generic-function-is-instantiated-per-call.md)'s trap would make every `T` ever put in an `Array` need an `operator==`. Writing that found that **`[T]` and `{K: V}` had never been lowered**: record [0022](0022-the-standard-library-and-what-is-sugar.md) makes all three spellings written form for a class and only `T[]` was ever rewritten, so `let l : [i32]` compiled and then answered to no method while `List<i32>` worked -- the sugar reached the literal and not the annotation. One rewrite serves the three now, and `TYPE_LIST` and `TYPE_HASH` are **gone**: nothing built one after it and nothing had ever emitted one. And that **a cast read no reference**: record [0049](0049-a-cast-is-a-closed-list.md)'s list was asked about the written types, so `symbol as char*` was on it and `symbol& as char*` was not -- and a `for x in` loop variable is a reference ([0040](0040-for-in-is-an-iterator.md)), which made the README's own tour not compile. `may_cast` reads through one now, **joining** the base chain rather than replacing it: reading through both sides of `circle_ref as Shape&` leaves the slice that entry refuses |

The parser branch is shared with the bare name and the spacing rule still decides. Behind it were four silent holes: the clone was appended to the **root**, which for a method makes a free function that has lost its `this` (`b.class(3)` came out of the emitter); the statement checker kept its walked set **by root declaration**, so a clone growing inside a class it had already walked was never typed — only a call an `if` or a `return` holds reaches that; two instantiations of one method carried **one C++ name**, since [0020](0020-the-base-chain-in-a-lookup.md) names a method by its parameters and a clone copies the token, so the name comes from the symbol table now; and a generic method **nobody calls** was emitted, naming a parameter nothing bound. A list written where there is no call — `b.take<i32>` or `b.n<i32>` — is **refused**; one written on a call to something not generic is silently ignored, for a method and a free function alike, which is one decision about both |
| 1.45 | Whether a generic class may be **derived from** with its own parameter | `decided` — [0056](0056-a-generic-may-derive-from-a-generic.md), 2026-09-09, and the answer is **yes**: it works, and record 0002's machinery already carried it. | 1.39 | What `as` may do, and how many spellings a cast has | `decided` — [0049](0049-a-cast-is-a-closed-list.md), 2026-09-09, and built. `as` was **C's cast**: `ExpressionTyper::cast` typed its operand for the record's sake and checked **nothing**, so `pt as i32` passed `hdc` and died in g++ with a mangled name. | 1.38 | What the language expects of the **programmer**, and when the compiler may refuse | `decided` — [0047](0047-what-the-language-expects-of-the-programmer.md), 2026-09-09.
